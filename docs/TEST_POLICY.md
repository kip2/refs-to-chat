# テスト方針

この拡張を、どのテストで、どこまで確かめるかをまとめます。
テストのしくみは [ARCHITECTURE.md](ARCHITECTURE.md) の 10 章、コマンドは [DEVELOPMENT.md](DEVELOPMENT.md)、人が確かめる手順は [MANUAL_TEST.md](MANUAL_TEST.md) にあります。

## 考え方

- できるだけ自動テストで確かめる。人が確かめるのは、自動にできないものだけにする
- 公式拡張（公式の Claude Code 拡張）のチャットには、何も送信しない

## テストの種類

| 種類 | コマンド | 何を確かめるか | 公式拡張 | ログイン | CI |
| --- | --- | --- | --- | --- | --- |
| ユニット | `npm test` | 部品ごとの動き。参照の作り方、メニューの表示条件など | 使わない | 要らない | 動く |
| 統合（公式拡張なし） | `npm run test:integration` | 本物の VS Code の上で、公式拡張がないときの動き | 使わない | 要らない | 動かさない |
| 統合（偽の公式拡張） | 同上 | 公式のコマンドを呼ぶ順番と、そのときの前面のエディタ・選択範囲 | 偽物を使う | 要らない | 動かさない |
| E2E | `npm run test:e2e` | 本物の公式拡張のチャットの入力欄に、本当に参照が入るか | 本物を使う | **要る** | 動かさない |
| 手動 | [MANUAL_TEST.md](MANUAL_TEST.md) | 自動にできないもの（Remote、起動の直後、制限モードなど） | 本物を使う | 要る | — |

「偽の公式拡張」は、公式拡張と同じ ID のコマンドを持つ、テスト用の拡張です（`src/test/fixtures/fake-claude-code/`）。
呼ばれた瞬間の状態を記録するので、ログインなしで確かめられます。

## E2E テストにはログインが要る

**E2E テストは本物の公式拡張を動かすので、公式拡張へのログインが要ります。**
ログインしていないとチャットの入力欄が出てこないので、テストは最初に失敗します。

- 初めて動かす前と、ログインが切れたときは、`npm run test:e2e:setup` を実行する。起動したテスト用の VS Code でチャットを開き、ログインしてから閉じる
- 自分のアカウントで動く（ログインは PC 全体で共通）。ログインが要るので、CI では動かさない
- 一部のテストだけを流すときは、環境変数 `E2E_GREP` にテスト名の一部を入れる（例: `E2E_GREP="貼り付けで入る" npm run test:e2e`）

失敗したテストの画面は `.vscode-test/e2e/screenshots/` に残ります。チャットの中身も写るので、人に見せるときは気をつけてください。

## テストを足すとき

- まず、いちばん手軽なテスト（ユニット → 統合 → E2E の順）で確かめられないかを考える
- 手動の項目を自動にしたら、[MANUAL_TEST.md](MANUAL_TEST.md) からその項目を消す
- テストが偶然通っていないかを、確かめたい処理をわざと壊して確かめる
- E2E のテストを書くときは、[ARCHITECTURE.md](ARCHITECTURE.md) の 10 章の「E2E テストで守ること」に従う
