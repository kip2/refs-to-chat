# 手動テストの手順

自動テスト（`npm test`・`npm run test:integration`）では、公式の Claude Code 拡張を無効にしています。
そのため、「チャットの入力欄に参照が本当に入るか」は、人が VS Code で確かめる必要があります。
リリースの前に、この手順で確かめてください。

## 準備

1. VSIX を作って入れる

   ```bash
   npm run package
   code --install-extension right-click-mention-<バージョン>.vsix
   ```

   同じバージョンのまま入れ直すと、VS Code が古い設定を覚えたままになり、変更が反映されないことがあります。
   試すたびに `package.json` の `version` を上げるか、VS Code を終了して `%APPDATA%\Code\CachedProfilesData\__default__profile__\extensions.user.cache` を消してください。

2. コマンドパレット（`Ctrl+Shift+P`）で「Developer: Reload Window」を実行する
3. 公式の Claude Code 拡張が入っていて、ログインしていることを確かめる
4. 拡張機能ビューで、`Right Click Mention` が今回のバージョンになっていることを確かめる

結果は、下の表の「結果」の列に ✅ / ❌ で書き込みます。
❌ のときは、何が起きたかをメモし、公式拡張のログ（出力パネル →「Claude VSCode」）も見てください。

## A. エディタから追加する

| No. | 手順 | 期待する結果 | 結果 |
| --- | --- | --- | --- |
| A-1 | ファイルを開き、数行を選んで右クリック →「選択範囲をClaudeのチャットに追加」 | チャットの入力欄に `@ファイル#開始-終了` が入る。選択範囲はそのまま | |
| A-2 | 何も選ばずに右クリック →「このファイルをClaudeのチャットに追加」 | `@ファイル` が入る | |
| A-3 | 行末まで選んで（選択が次の行の先頭で終わる状態で）A-1 をする | 行番号は、文字を選んでいる最後の行までになる | |
| A-4 | コマンドパレットで「Right Click Mention: このファイルをClaudeのチャットに追加」 | A-2 と同じ | |
| A-5 | ファイルを 1 つも開いていない状態（チャットもエディタのタブで開いていない）でコマンドパレットを開く | 「Right Click Mention: …」のコマンドが出てこない | |
| A-6 | Claude のチャットだけをエディタのタブで開いた状態でコマンドパレットを開く | 「Right Click Mention: …」のコマンドが出てこない | |
| A-7 | ファイルを開いたうえで、Claude のチャットのタブを前面にしてコマンドパレットを開く | 「Right Click Mention: …」のコマンドが出てこない（チャットが前面だと、公式コマンドが参照を作れないため） | |

## B. エクスプローラーから追加する

| No. | 手順 | 期待する結果 | 結果 |
| --- | --- | --- | --- |
| B-1 | 開いていないファイルを右クリック →「Claudeのチャットに追加」 | `@ファイル` が入る。一瞬開いたタブは閉じる | |
| B-2 | 開いているファイル（範囲を選んでおく）を右クリックして追加 | `@ファイル`（行番号なし）が入る。タブは残り、選択範囲もそのまま | |
| B-3 | 別のエディタグループ（右側など）にだけ開いているファイルを、左側のグループを選んだ状態で追加 | 入ったあと、左側に一瞬できたタブは閉じる。右側のタブは残る | |
| B-4 | ファイルを 3 つ選んで追加 | 3 つとも入る。タブは残らない | |
| B-5 | フォルダを右クリックして追加 | `@フォルダ/` がチャットの入力欄に貼り付けられ、「チャットに貼り付けました」の通知が出る | |
| B-6 | 画像ファイル（`.png` など）を追加 | `@画像` が貼り付けられる | |
| B-7 | ファイルとフォルダを混ぜて選んで追加 | ファイルはそれぞれ入り、フォルダは最後にまとめて貼り付けられる | |
| B-8 | プレビュー（斜体のタブ）で別のファイルを開いた状態で B-1 をする | プレビューのタブは消えない | |

## C. チャットの状態による違い

| No. | 手順 | 期待する結果 | 結果 |
| --- | --- | --- | --- |
| C-1 | Claude のチャットを閉じた状態で A-1 をする | チャットが開き、参照が入る | |
| C-2 | チャットをサイドバー（左右の領域）に出した状態で A-1・B-1・B-5 をする | どれも入る | |
| C-3 | チャットをエディタのタブで開いた状態で A-1・B-1・B-5 をする | どれも入る。A-1 は選択範囲の行番号付き | |
| C-4 | 「Developer: Reload Window」の直後（チャットが起動しきる前）に A-1 をする | 入る。入らなかった場合は、チャットの読み込みが終わってからもう一度試すと入る | |

## D. うまくいかないときの動き

| No. | 手順 | 期待する結果 | 結果 |
| --- | --- | --- | --- |
| D-1 | 公式の Claude Code 拡張を無効にして A-1 をする | 参照がクリップボードにコピーされ、「公式の Claude Code 拡張（anthropic.claude-code）が見つかりません」の警告が出る | |
| D-2 | 公式拡張を無効にしたまま、フォルダとファイルを選んで追加 | 全部の参照が空白でつながって 1 回だけコピーされ、警告も 1 回だけ出る | |
| D-3 | 設定 `claudeCode.useTerminal` を `true` にする | 右クリックメニューにもコマンドパレットにも出てこない（試したら元に戻す） | |
| D-4 | 信頼していないワークスペース（制限モード）でフォルダを開く | 右クリックメニューに出てこない | |

## E. Remote（WSL・SSH）

手元の PC に入れるだけで動くことを確かめます。リモート側には入れないでください。

| No. | 手順 | 期待する結果 | 結果 |
| --- | --- | --- | --- |
| E-1 | 「WSL: Connect to WSL」で WSL のフォルダを開き、A-1・B-1・B-5 をする | どれも入る（参照のパスは WSL 側のパス） | |
| E-2 | Remote-SSH で SSH 先のフォルダを開き、A-1・B-1・B-5 をする | どれも入る | |
| E-3 | E-1・E-2 で、拡張機能ビューの「ローカル - インストール済み」に `Right Click Mention` があり、リモート側に入れていないことを確かめる | リモート側に入れなくても動いている | |

Remote で公式拡張がリモート側に入っていない場合は、公式拡張の案内に従ってリモート側に入れてください（この拡張ではなく、公式拡張の都合です）。

- ❌ があれば、Issue にするか、直してからもう一度この手順を通す
